# 使用教程：从打开设置页到手机能用

这份文档只讲**在设置页里怎么点、填什么、看到什么才算成功**。
字段的技术含义与取值格式见 [CONFIGURATION.md](CONFIGURATION.md)。

> 前提：这台电脑上已装好 `dsh-tunnel` 插件，并且**已经有一个可用的 frp 服务器**（frps 已运行、公网域名已解析到它、反向代理已把域名转发到 frps 的代理端口）。服务器侧不归本插件管。

---

## 0. 先看「状态」卡：三个数决定你能不能往下走

打开设置页（两处入口任选）：

- 侧栏最底部的隧道图标（带小圆点，灰=未连、黄=连接中、绿=已连接）
- **设置 → 公网隧道**

先看第一张「状态」卡：

| 显示 | 含义 | 不满足时怎么办 |
|---|---|---|
| `DSH 监听` = `http://127.0.0.1:<端口>` | 插件的运行环境正常 | 若是空/异常，重启 DSH |
| `frpc 版本` = 具体版本号（如 `0.71.1`） | 插件找到了 `frpc` 可执行文件 | 显示「未知」或路径里有「请把 frpc…」→ 见下方「装 frpc」 |
| `frpc 路径` = 一个真实路径 | 用的是哪个二进制 | 同上 |

### 装 frpc（只在显示「缺少 frpc」时需要）

1. 去 frp 官方 release 下载**与服务器同版本**的 **`windows_amd64`** 包（不要下成 `linux_amd64`）。
2. 解压出 `frpc.exe`，放到：

   ```
   C:\Users\<你的用户名>\.dsh\dsh-tunnel\bin\frpc.exe
   ```

3. 杀毒软件（如火绒）里把 **`...\.dsh\dsh-tunnel\bin` 这个目录**加入信任区。
   > 刚放进去的 `frpc.exe` 第一次执行常被杀软扫描锁住，报 `Access is denied`；把目录加进信任区后点一次「重启隧道」即可。插件会把这类错误翻译成「被杀软或权限拦住」。
4. 回到设置页按 F5 或点「刷新」，`frpc 版本` 应出现具体版本号。

---

## 1. 填「隧道参数」（只填 6 格）

这张卡里有 12 格，但**通常只需要填 6 格**，其余保持默认。

| 设置页里的名字 | 填什么 | 举例 |
|---|---|---|
| **frp 服务器地址** | frps 的地址，**只写域名或 IP**，不带 `http://`、不带端口 | `vps.example.com` 或 `8.130.36.4` |
| **frp 控制端口** | frps 的 `bindPort`（不是公网 443） | `7000` |
| **公网地址（手机填写）** | 手机上要填的服务地址，**必须带协议**，不带路径 | `https://dsh.example.com` |
| **服务器内部代理端口** | frps 暴露给反向代理的端口，必须落在服务器 `allowPorts` 里 | `19098` |
| **frp 版本（与服务器一致）** | 服务器上 frps 的版本 | `0.71.1` |
| **配置格式** | frp ≥ v0.52 选 `toml (v0.52+)`，更早选 `ini` | `toml (v0.52+)` |

**保持默认的格子**：代理名（`dsh-desktop`，两台电脑不能重复）、本机目标地址（`127.0.0.1`）、frpc 路径（留空=自动查找托管目录）、TLS ServerName（留空）、登录 Cookie 有效期（`3650`）、额外受信 Host（留空，除非要局域网直连）。

**三个勾选框**：

| 勾选框 | 建议 |
|---|---|
| 随 DSH 自动启动隧道 | **先不勾**。等手动验证成功后再勾，避免出错时每次启动都重试 |
| 启用传送 TLS | **必须勾**（服务器 `transport.tls.force = true` 时，不勾必定登录失败） |
| 自动写入 DSH 信任配置 | 保持勾选。它会在插件启动时把公网地址写进 DSH 的受信列表 |

填好后点 **保存**。

> 保存会**重新加载插件**（界面短暂断开几百毫秒是正常的），并立即重建 frpc 配置。

## 2. 填「frp 密钥」

### 这串密钥是什么

`frp` 的 token 是 **frps 与 frpc 之间的共享口令**，用来防止别人连你的隧道。

它**不是**插件生成的、**不是** DSH 生成的、**也不是** frps 自动生成的。
它由**搭建服务器的人**决定：写死在服务器 frps 配置的 `auth.token` 里，然后每一个客户端（每一台电脑的 frpc）都必须填**一模一样**的那一串。两边不一致，frps 就会拒绝登录，日志是：

```
connect to server error: token in login doesn't match token from configuration
```

### 从哪里取

**情况 A：服务器是你自己按本项目第二层部署的**

登录服务器，在项目目录里读配置（这是你唯一需要碰"文件"的地方，而且是在服务器上，不是在你电脑上）：

```bash
cd /home/dev/project_code/seeder-machine-server
sudo grep -i 'auth.token' data/frps/frps.toml
```

输出形如 `auth.token = "64位十六进制"`，引号里的那串就是要填的密钥。

> 如果这条路走不通、或者这串已经丢失/怀疑泄露：重新生成一个并让两端同时更新（见下方「轮换」）。

**情况 B：服务器是别人搭的**

直接向他要 token，或者让他把你加进 `auth.token` 的共享范围。没有别的办法——这是共享密钥。

**情况 C：你不知道服务器在哪、也没有配置权限**

那这台电脑上的插件无论如何都不可能连上。先解决服务器。

### 怎么填

把密钥粘贴进输入框 → 点 **保存**。
卡片标题会变成 `frp 密钥 · 已保存 · 64 个字符`。

> 这里只显示**长度**，永远不显示内容。如果长度明显不对（例如只有 8 个字符），卡片会给出黄字提醒——说明粘贴时漏了后半段。

### 轮换（怀疑泄露时）

1. 服务器生成新值并改配置：
   ```bash
   openssl rand -hex 32
   # 写进 data/frps/frps.toml 的 auth.token
   docker compose restart frps
   ```
2. 在本页重新保存新的密钥，然后点「重启隧道」。
3. 隧道会短暂中断，恢复即可。

## 3. 让 DSH 接受这个域名（「DSH 信任配置」卡）

DSH 只接受回环地址、它自己监听的地址，或受信列表里的 Host。公网域名必须进列表。

点 **应用**。然后看卡片里的「状态」：

| 显示 | 含义 | 下一步 |
|---|---|---|
| 已生效 | 当前 DSH 进程已经接受公网 Host | 继续第 4 步 |
| 需要重启 DSH | 配置已写入，但当前进程还没加载 | **重启 DSH**（关窗重开），回来后这一行会变成「已生效」 |

顶部徽标里的黄字「需要重启 DSH」也是同一件事。

> 「恢复默认」会把这一行补丁整行删掉，回到 DSH 出厂状态——卸载前用它清理。

---

## 4. 启动隧道并确认连上了

点「状态」卡右上角的 **启动**。

### 看徽标

顶部徽标会依次经过：`启动中` → `运行中` → `已连接`。

- **运行中**（黄）：进程起来了，但还没跟服务器握手成功
- **已连接**（绿）：登录成功且代理已就绪，手机可以连了

### 看日志（「frpc 日志」卡 → 展开日志）

成功的标志是两行：

```
login to server success
[dsh-desktop] start proxy success
```

### 常见失败对照

| 日志里出现 | 原因 | 处理 |
|---|---|---|
| `token in login doesn't match token from configuration` | 密钥不对 | 回第 2 步重新取/重新粘贴 |
| `TLS handshake failed`、`first record does not look like a TLS handshake` | 两端 TLS 设置不一致 | 勾上「启用传送 TLS」；若服务器还要求证书名，再填 TLS ServerName |
| 登录成功但没有 `start proxy success` | `remotePort` 不在服务器的 `allowPorts` 里 | 改成服务器允许的那个端口（本项目是 `19098`），或改服务器 |
| `frpc version mismatch` | 两端版本不同 | 换成与 frps 同版本的 `frpc.exe` |
| `connect: connection refused` / 超时 | 控制端口不通 | 检查安全组/防火墙是否放行 `serverPort` |

## 5. 手机登录

在「手机登录」卡：

1. 点 **显示访问密钥**，再点 **复制**。
2. 手机打开 DSH-Harmony，填写：
   - 服务地址：`公网地址`（例如 `https://dsh.example.com`）
   - 登录方式：**访问密钥**
   - 密钥：上一步复制的内容
3. 登录成功后，**关掉 Wi-Fi 用蜂窝网络再试一次**，确认走的是公网而不是局域网。

> 访问密钥属于**当前 DSH 进程**，每次重启都会变。手机登录后靠 Cookie 免填，Cookie 有效期由「登录 Cookie 有效期」决定（默认 3650 天）。
> 这串密钥等于整台电脑的控制权：不要截图、不要发聊天、不要贴到公开地方。

---

## 6. 让它长期可用

1. 勾上 **随 DSH 自动启动隧道** → 保存。
2. 滚到「开机自启」卡 → 点 **创建启动项**（在当前用户的「启动」文件夹放一个快捷方式，不需管理员权限）。
3. 重启电脑 → 登录 Windows → DSH 自动打开 → 隧道自动连上 → 手机照常可用。

**明确限制**：DSH 桌面进程没运行时手机不可达。要「电脑开着但没开 DSH 也能连」，需要另一套形态（专用无界面实例），不在本插件 V1 范围内。

---

## 7. 换电脑 / 换服务器

- **换电脑**：装 DSH → 装插件 → 「迁移到另一台电脑」里 **导入配置**（JSON，不含任何密钥）→ 重新填 frp 密钥 → 应用信任 → 重启 DSH → 手机（域名不变时）不用改地址。
- **换服务器**：改服务器地址/控制端口/内部代理端口/frp 版本，重新填新服务器的 token。
- **换域名**：改「公网地址」→ 保存 → 应用 → 重启 DSH → 手机改地址并**重新登录一次**（Cookie 绑定域名）。

## 8. 出错时怎么自助排查

按这个顺序看，基本能定位在哪一段：1. **状态卡**：`DSH 监听` 有端口吗？`frpc 版本` 有值吗？「最近错误」写了什么？
2. **日志卡**：展开看最后几行，对照第 4 步的失败对照表。
3. **服务器侧**（需要服务器权限）：
   ```bash
   docker logs --tail 50 frps       # 有没有收到 client login
   ss -lntp | grep 7000             # 控制端口在听
   ss -lntp | grep 19098            # 有 frpc 连上后才会出现
   docker exec nginx nginx -t       # 反代配置是否有效
   ```
4. **公网入口**：在任意能上网的机器上
   ```bash
   curl -I https://dsh.example.com
   ```
   - `502`：Nginx 到了 frps，但隧道没建立 → 回到第 4 步
   - `403` / `Untrusted`：隧道通了，但 DSH 不认这个 Host → 回到第 3 步（信任配置是否「已生效」）
   - `200` / 登录页：链路全通

### DSH 完全打不开（设置页都进不去）

若 DSH 弹窗提示「应用无法启动或已意外停止」，并在诊断报告里看到：

```
Failed plugins (1):
  credentials
    TypeError: credential key "dsh-tunnel:frp-token" must be "<scope>/<id>"
```

说明**凭据文件里有一条键不合法的记录**。DSH 在启动时解析凭据文档，一条坏记录会让 `credentials` 服务失败——而它是必需服务，于是整个 DSH 起不来（`connection` 等一排插件都在等它）。

> 为什么会这样：DSH 的凭据键必须是 `<scope>/<id>`，两段都要匹配 `^[a-z][a-z0-9-]*$`。**0.1.0–0.1.4 用了冒号** `dsh-tunnel:frp-token`，不合法。0.1.5 起改为 `dsh-tunnel/frp-token`。
> 插件自身没法自动修复：能修复它的那个服务，正是加载失败的那个。

修复步骤：

1. 退出 DSH。
2. 打开 `%USERPROFILE%\.dsh\.credentials.yaml`。
3. 把 `dsh-tunnel:frp-token` 改成 `dsh-tunnel/frp-token`（值保持不变），或把这一小段整体删掉。
4. 启动 DSH；若删掉了记录，回到第 2 步重新保存一次密钥。
